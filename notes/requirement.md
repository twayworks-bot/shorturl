## [1차 요구사항] (2026-10-17 13:44)
- **원본 요청**:
  > 긴 url을 단축링크(short url)로 제공하는 서비스앱을 제공하려합니다. shorturl은 https://domain/shorturl로 제공하고 web up대시보드에서 사용자가 long url을 입력하면 short url을 제공하는 방식으로 사용자 편의성을 제공합니다.
- **확정된 세부 사항**:
  1. **기술 스택**: FastAPI + SQLite + 모던 HTML/JS (REST API 자동 문서화 포함)
  2. **핵심 편의 기능**:
     - 클릭 수(조회수) 통계 및 최근 생성된 URL 목록 대시보드 표시
     - 사용자 지정 단축 코드(Custom Alias) 직접 입력 기능
     - 생성된 단축 URL의 QR 코드 생성 및 클립보드 복사 버튼 제공
     - 만료 기한(Expiration Date) 설정 및 링크 삭제 기능
  3. **접근 방식**: 별도 로그인 없이 누구나 바로 생성하고 목록을 확인하는 공개형 대시보드

  > ui dashboard에서 이미 만들어진 링크를 찾고 관리할 수 있도록 해주세요. 특히 메타정보를 강제 갱신할 수 있도록 리프레시 버튼도 추가해주세요.
  > 내용을 검토하고 개발 계획을 수립해주세요. 세한 구현요구사항과 기능 정의등을 기술하고, 개발세부내역, 기능, 팩키지 구성도, 기능세부 내역설명, 개발 검토시 필요한 제약사항, 추가 개발 제안 내용을 notes\SPECIFICATION.md에 기록하시오.
  > 요구사항을 바탕으로 최소 구현해야 하는 기능 MVP(minimun viable prodcut)를 정의하고, 개발 세부 요구 계획을 수립하여 notes\plan_YYYYMMDDHHmm.md에 기록 하시오.
  > 매번 개발 요구사항과 요약은 notes/history.md에 사용자 원본 요구사항과 계획 기록은 notes/req_YYYYMMDDHHmm.md에 산출물 생성 기록은 notes/result_YYYYMMDDHHmm.md에 기록을 항상 하시오. 모든 요구 사항은 누적하여 notes/requirement.md에 기록합니다.
- **핵심 추가 및 변경 요구사항**:
  1. **라우팅 명확화**:
     - 기본 루트 패스(`/`)는 웹 UI 대시보드 제공
     - 하위 패스(`/{shorturl}`)는 매핑된 타겟 사이트로 연결하되 **중간 랜딩 페이지**를 통해 전달 (`?direct=1` 요청 시 즉시 리다이렉트도 지원 가능)
  2. **타겟 사이트 메타정보(Open Graph / HTML Meta) 수집 및 중간 랜딩 페이지 제공**:
     - 타겟 대상 사이트의 제목(`meta_title`), 미리보기 설명(`meta_description`), 대표 이미지(`meta_image`), 파비콘(`favicon_url`)을 수집하여 SQLite에 저장
     - `/{shorturl}` 접속 시 타겟 사이트의 메타정보(제목, 미리보기 설명, 이미지 등)를 한눈에 볼 수 있는 **중간 랜딩 페이지(`landing.html`)** 제공 및 원본 사이트 이동 지원
  3. **SQLite 기반 매핑 및 생성 후 1년(365일) 경과 시 링크 소멸 정책**:
     - 생성 시 만료일을 별도로 지정하지 않으면 기본 `created_at + 1년(365일)`로 만료일 자동 설정
     - 1년이 경과하거나 만료된 링크는 접근 차단(`410 Gone`) 및 만료 링크 일괄 소멸(Purge) 기능 지원
  4. **UI 대시보드 링크 검색/관리 및 메타정보 강제 갱신(Refresh) 버튼**:
     - 대시보드에서 기존 생성된 링크를 검색/필터링하고 메타 미리보기 정보를 확인
     - 각 링크마다 **메타정보 강제 갱신(리프레시) 버튼**을 추가하여 클릭 시 대상 사이트의 최신 메타데이터를 다시 크롤링·업데이트
  5. **문서화 산출물 관리 규칙**:
     - `notes/SPECIFICATION.md`: 상세 구현 요구사항, 기능 정의, 패키지 구성도, 기능 세부 설명, 제약사항, 추가 개발 제안 기록
     - `notes/plan_YYYYMMDDHHmm.md`: MVP 정의 및 개발 세부 계획 기록
     - `notes/history.md`: 매번 개발 요구사항과 요약 누적 기록
     - `notes/req_YYYYMMDDHHmm.md`: 사용자 원본 요구사항과 계획 기록
     - `notes/result_YYYYMMDDHHmm.md`: 산출물 생성 및 검증 결과 기록
     - `notes/requirement.md`: 모든 요구사항 누적 기록

  > 시작 CMD: Gunicorn 또는 Uvicorn (포트 5000) 참조 생성
  > 이 프로젝트의 목적과 사용법, 기능설명은 README.md에 수정하여 기록하고, 웹앱의 배포방법과 구현 내용과 실행방법도 동일하게 README.md에 기록을 유지해 주세요.
- **핵심 요구사항**:
  1. `Dockerfile` 생성 (SQLite Persistent Volume `DB_PATH`, 포트 `5000`, `DEFAULT_PREFIX`, `HEALTHCHECK` `{prefix}/api/status`, 시작 `CMD`)
  2. 애플리케이션에 `DB_PATH` 볼륨 경로 연동 및 `{prefix}/api/status` 헬스체크 엔드포인트 추가
  3. `README.md`에 프로젝트 목적, 기능, 구현 내용, 실행 방법 및 Docker 배포 방법 업데이트
